G2为主执行者自查，尚未做独立执行者审查。第一版交付不代表长期阶段门禁、完整录屏或导师评审完成。

## v0.2（2026-09-30 至 2026-10-01）

| 决策 | 理由 / 验证边界 |
| --- | --- |
| 以规则实现条件助手与政策追问 | 用户先体验后续功能；不依赖未提供的模型密钥。页面和API明确未接模型，完整RAG继续待实施 |
| 三名子agent按独立文件分工 | 岗位助手、政策查询、独立审查分离；主agent负责接口集成、业务修复、隔离验证和交付，不把子agent完成声明作为验收 |
| 默认SQLite不迁库、不复位 | 保留用户体验数据；先在线备份，再重启新版。业务表数量和原有统计经校验保持一致 |
| 临时MySQL8.0.45验证 | 已安装的官方mysqld另起13307实例，独立随机库/凭据，Windows ASCII数据路径及no-monitor；测试完停止自有进程，不修改MySQL80服务 |
| 应用MySQL使用READ COMMITTED | 独立审查在默认REPEATABLE READ复现名额超额与跨单位累计旧快照；切换后名额测试通过 |
| 工时重算刷新持久化排序字段 | DATETIME(0)舍入造成新对象微秒与旧记录秒精度混用；.750000固定用例实机复现，flush后populate_existing修复，92项全量MySQL回归通过 |
| 不做DATETIME(6)结构迁移 | 本轮通过统一读取持久化值修复排序，沿用原始ID作为同时间次序；后续若要求微秒精度再作显式迁移 |

本轮独立审查覆盖新模块、权限边界、名额、工时与政策导入，新增回归均通过；不等同整份计划的全面G2验收。v0.1报告保留其当时状态，v0.2实际结果见acceptance/REPORT-v02.md。

## MySQL正式切换及官方资料（2026-10-01）

| 决策 | 理由 / 验证边界 |
| --- | --- |
| 用户要求后正式迁移原SQLite数据 | 逐表全字段比对、私有配置快照和完整SQL备份完成后才激活.env；原SQLite保留，正式库不复位 |
| 另起13308专用持久实例 | 已装官方MySQL8.0.45，但原3306账号未提供；独立数据目录和随机凭据，不重置root或修改现有MySQL80服务 |
| MySQL目录放ASCII LocalAppData | Windows原生mysqld不能使用含“毕设”的数据路径；修正商店应用目录重定向导致的逻辑/物理路径差异，归属检查双方都取真实路径 |
| schema0002升级DATETIME(6) | SQLite历史有微秒，迁移至DATETIME(0)会舍入；显式升级保留时间，原有刷新持久化排序字段逻辑继续保留 |
| 数据库排序规则utf8mb4_0900_as_cs | 保持原SQLite账号大小写区分，避免迁移后用户名碰撞；隔离MySQL实例使用同一排序规则验证 |
| 将备份恢复到独立13307 | 实测SQL可恢复并比对升级后的全行哈希；最新MySQL100通过，生产库只读核对，不用生产库做破坏性测试 |
| 官方资料由子agent研究、主agent复核 | 14条来源、原文、日期和适用范围归档；主agent重新核对5页原句和省政府正文/附件、44项文件哈希，不用搜索摘要代替正文 |
| 新资料暂不导入当前问答库 | 当前policy_doc没有时效和历史检索完整机制；已截止招聘和现行性不明资料不能混成当前学校规则。本校完整现行细则、具体时薪和2020困难认定全文仍待取得 |

本轮测试与部署结果见acceptance/REPORT-MySQL.md。前端和业务规则未在数据库切换中改版；不将迁库或资料搜集计作模型RAG验收。
