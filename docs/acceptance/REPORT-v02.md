## 本轮交付范围

学生岗位助手按明确条件查询真实演示库中的当前可申请岗位，显示生效条件、未理解表述、四维规则分数和缺失档案。只读业务数据，用户从详情自行申请。每条问题独立解析；最多8条结果、20条本人历史，历史结果按当前岗位重算。

政策原文查询支持主题别名、中文/数字条款编号、同用户同会话的有限追问、新会话与本人历史。结论只呈现真实原文和来源，不调用大模型。未知新主题不借旧主题作答；学校细则缺失仍明确无依据。

本轮没有接LLM/BGE/Chroma，不声称完成完整RAG或其12题评测。当前默认SQLite数据没有迁入MySQL。完整录屏、学校正式制度和导师验收要求继续待补齐。

已修复且回归通过的问题：

1. 已满关闭岗位允许清空工作时段，调额或学生撤销后会以无时段自动重开。现在published及closed/full编辑均需有效时段；拒绝修改不新增成功审计。
2. 政策导入直接丢弃时区导致未来核验时间被误接收。现在先转中国本地时间，再判断未来与保存；UTC/日本时区测试通过。
3. 未知新政策主题继承上一条工时问题，产生无关引用。现在只有明确、有限的追问模式能继承主题。
4. 否定单位全名又命中其短别名，或非技能条件的“或”改变技能关系。最长别名覆盖和技能局部关系解析已修复。
5. MySQL默认REPEATABLE READ下，认证读取建立旧快照，后续行锁后的计数/跨单位累计仍过期。实机修复前2名额3次批准均200，两单位各5小时均normal；应用改READ COMMITTED。
6. READ COMMITTED全量首次仍有1项工时失败。MySQL DATETIME(0)舍入与SQLAlchemy新对象微秒混用使排序反转、两次即时响应均normal；固定.750000实机用例稳定复现。flush后链尾查询populate_existing，统一持久化精度与ID排序；全量92通过。
7. Windows打印MySQL测试结果的GBK/UTF-8编码冲突。验证脚本统一UTF-8，先保存结果再打印，finally仍关闭自有临时实例。

修复前诊断XML存于忽略的work目录，不覆盖正式通过报告。MySQL验证使用安装好的官方mysqld，13307端口、随机专用库与账号、独立数据目录、no-monitor，无外部下载；结束后临时进程停止，不更改用户MySQL80服务或应用.env。
